# ADR-0032: Security follow-ups (Phase 11d)
Status: Proposed. Builds on [ADR-0024](0024-hardening.md).

## Decisions
- **Upload scanning is a configuration choice.** Every upload already went through an `IFileScanner`; the default accepts everything. `Scanning:Provider=ClamAv` now streams each file to a ClamAV daemon (INSTREAM) and refuses a file reported infected. **A scanner that cannot be reached or gives an answer that is not understood refuses the upload** by default (`FailClosed`); the operator can choose to fail open. The scanner is registered before the modules, which only add the do-nothing scanner when none is registered.
- **Column-level encryption, for contact details first.** Visitors' e-mail and phone are stored with AES-256-GCM. A key ring comes from the operator's configuration (a key vault or secret store), never the database; each value is stored as `enc1:<key id>:<nonce, tag, ciphertext>` so keys can be **rotated** (new values use the current key, old values stay readable while their key is kept). The column's name is bound in as associated data, so a value moved to another column does not decrypt. A value without the prefix is read as plain text (data from before encryption was turned on), and `Fms.Migrator --encrypt-existing` protects it (and re-protects values written with an older key). With no key configured, values are stored readable; `Encryption:Required` makes start-up fail instead. Chosen because they are personal data of people who are not users and are not searched anywhere. **Not encrypted:** users' sign-in e-mail (how people are found at sign-in), vendor and contact details (searched: **corrected in [ADR-0034](0034-vendor-contact-encryption.md), they are not and are now encrypted**), lease terms. Database-level encryption (TDE) remains the operator's responsibility and covers everything.
- **A shared counter for the guessable routes.** The per-server rate limit let an attacker multiply guesses at a secret address by the number of servers. With `Security:RateLimit:Shared=true`, requests to the secret-address routes are also counted per client address and minute in the database, one small write per such request. If the counter cannot be reached the request goes on (the per-server limit still applies), so a counter fault does not close the visitor passes. Off by default: one server needs no shared counter.
- **A passive ZAP scan, run by hand.** A workflow and a script mode run an OWASP ZAP baseline scan against the production web image in front of the API. It is not a gate and not part of every pull request; findings are triaged in `docs/security/zap.md`.

## Consequences
- A lost key means lost contact details. Keys must be backed up apart from the database.
- Encrypted columns cannot be searched or sorted in the database. Visitors' search by name and company is unaffected.
- The ZAP workflow and script mode have not been run (the image could not be downloaded where they were written); the first run may need changes.
- Only one column group is encrypted. Adding another is a converter on the property, a migration if the column must widen, and a run of `--encrypt-existing` extended to it.
